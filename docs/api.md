# API

Base URL: `http://localhost:3000`. Send JSON with `Content-Type: application/json`. IDs and timestamps are generated by the server. Unknown body fields are rejected; the history endpoint also rejects unknown query fields.

Amounts must be positive decimal strings with at most two fractional digits; no rounding is performed. A single unspecified currency is assumed. Amounts and balances are returned with two decimal places and limited to `90071992547409.91`. Names, descriptions, and references must be nonempty and cannot contain null characters; surrounding whitespace is trimmed. References are limited to 256 UTF-8 bytes after trimming and are unique per account. A duplicate returns 409 even when the request body differs; it does not replay the original response.

## Create accounts

```sh
curl -sS -X POST http://localhost:3000/accounts -H 'Content-Type: application/json' -d '{"name":"Asha"}'
```

201 example: `{"id":"<uuid>","name":"Asha","balance":"0.00","created_at":"<timestamp>"}`. Save the returned ID as `SOURCE` in your shell.

## Post a transaction

```sh
curl -sS -X POST "http://localhost:3000/accounts/$SOURCE/transactions" -H 'Content-Type: application/json' -d '{"type":"credit","amount":"100.00","description":"Initial credit","reference_id":"credit-1"}'
```

201 example: `{"id":"<uuid>","account_id":"<uuid>","type":"credit","amount":"100.00","description":"Initial credit","reference_id":"credit-1","created_at":"<timestamp>"}`. `type` is `credit` or `debit`; debits cannot exceed the balance.

## Read balance and history

```sh
curl -sS "http://localhost:3000/accounts/$SOURCE/balance"
curl -sS "http://localhost:3000/accounts/$SOURCE/transactions?type=credit&page=1&limit=20"
```

Balance example: `{"account_id":"<uuid>","balance":"100.00"}`. History example: `{"data":[{"id":"<uuid>","account_id":"<uuid>","type":"credit","amount":"100.00","description":"Initial credit","reference_id":"credit-1","created_at":"<timestamp>"}],"pagination":{"page":1,"limit":20,"total_records":1,"total_pages":1}}`.

`type` is optional; `page` defaults to 1 and `limit` defaults to 20 (maximum 100). Empty results have zero total pages. Records sort by `created_at` descending, then ID descending for ties. Timestamps are transaction start times, not commit order; offset pages may shift between requests.

## Transfer bonus

Create a second account and save its ID as `DESTINATION`, then:

```sh
curl -sS -X POST http://localhost:3000/transfers -H 'Content-Type: application/json' -d "{\"source_account_id\":\"$SOURCE\",\"destination_account_id\":\"$DESTINATION\",\"amount\":\"30.00\",\"description\":\"Transfer\",\"reference_id\":\"transfer-1\"}"
```

201 returns `{"id":"<transfer uuid>","debit":{...},"credit":{...}}`; each entry has the same fields as a posted transaction. Accounts must differ and the reference must be unused on both accounts. Both entries and balances commit together or none do. This bonus does not perform external settlement.

## Errors

Errors have the form `{"error":{"code":"VALIDATION_ERROR","message":"Invalid request"}}`. Malformed input or IDs and balance overflow return 400; a missing account returns 404 `ACCOUNT_NOT_FOUND`; insufficient funds and duplicate references return 409 `INSUFFICIENT_FUNDS` or `DUPLICATE_REFERENCE`. Oversized JSON returns 413, unsupported encoding 415, and unexpected failures return 500 `INTERNAL_ERROR` without database details.

Unmatched routes use Express's default 404 response. The service has no authentication, authorization, tenant isolation, or rate limiting; use synthetic data locally only. Direct database writes bypass API validation and immutability.
